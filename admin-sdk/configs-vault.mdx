The `swiftbase-admin-sdk` provides administrative methods for reading and updating project authentication settings, social identity providers, and branding configurations.

## Project Authentication Configurations

Manage tenant-wide identity settings programmatically:

```typescript
import { getConfiguration, updateConfiguration } from "swiftbase-admin-sdk";

const projectId = "proj_01HZX87K9Z1X2Y3W4V5U6T7S8R";

// Fetch current project identity configuration
const config = await getConfiguration(projectId);
console.log("Allowed redirect URIs:", config.redirect_uris);
console.log("TOTP required:", config.totp_required);

// Update configuration policies
await updateConfiguration(projectId, {
  allow_registration: true,
  totp_enabled: true,
  totp_required: false,
  passkeys_enabled: true,
  primary_color: "#6366f1",
  redirect_uris: ["https://app.example.com/callback"],
});
```

## App Configs & Secrets (Vault)

Application feature flags, dynamic configuration schemas, and encrypted Vault secrets are managed via the Swiftbase REST API and runtime container injections:

- **App Configs**: Read and update published schemas via `GET /api/configs/:id` and `POST /api/configs/:id/publish`.
- **Encrypted Secrets (Vault)**: Store credentials, private keys, and API tokens securely in the Swiftbase Console or via `POST /api/vault/secrets`.
- **Automatic Container Injection**: Secrets assigned to a container deployment are automatically decrypted and injected as standard environment variables (`process.env.MY_SECRET`) at container runtime, eliminating the need to make runtime API requests to read credentials.
